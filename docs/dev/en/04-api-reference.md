# API & Protocols

> 中文版：[../zh/04-api-reference.md](../zh/04-api-reference.md)

The backend is a REST service mounted at `http://127.0.0.1:<port>/api/v1`, plus a handful of SSE streaming endpoints.

> The port is allocated dynamically by the Electron main process (`findFreePort`); running the sidecar standalone in development uses the fixed 8765.
> The authoritative endpoint list is the code — this page documents the conventions and the most-used layer only, rather than duplicating a table that goes stale quickly.
> For the complete list: start the backend and open `/docs` (the OpenAPI page FastAPI generates).

## Authentication

Every business router declares `dependencies=[Depends(require_token)]`:

```
Authorization: Bearer <token>
```

- The token is generated by the main process and injected into the sidecar via `FIREYEAUD_TOKEN`.
- **If the variable isn't set, no validation happens** (development convenience). Packaged builds always set it.
- `/health` needs no auth; it's used for startup probing.

## Error envelope

Anything non-2xx returns one structure:

```json
{
  "error": {
    "code": "E_NOT_FOUND",
    "messageKey": "error.notFound",
    "params": { "id": "F-0001" }
  }
}
```

`toApiError()` in the frontend's `lib/api/client.ts` reads this and rebuilds an `ApiError` (with `code` / `httpStatus` / `messageKey` / `params`).

`messageKey` is a translation key and must exist in the `error` namespace of `packages/shared/src/locales/{zh-CN,en-US}.ts`.

## SSE endpoints

Endpoints that need live feedback use POST + SSE, returning `text/event-stream` with one `data:` line per message.

### Event shape

```ts
interface SseEvent<T> {
  type: string;
  seq: number;       // increments from 1; the frontend processes in order
  sessionId: string;
  ts: string;        // ISO timestamp
  data: T;
}
```

### Event types

| type | data | Meaning |
|---|---|---|
| `status` | `{ phase }` | Phase change: `planning` / `executing` / `reflecting` / `compacting` / `reading` |
| `context` | `{ options }` | Snapshot of what this turn actually gave the model (model / databases / knowledge / MCP / skills / rules) |
| `token` | `{ delta }` | Body-text delta; appended to the current message |
| `tool_call` | `{ callId, tool, params }` | A tool call starts |
| `tool_result` | `{ callId, summary, ok }` | Tool result summary (full results are not sent to the frontend) |
| `notice` | `{ messageKey, params? }` | Informational, doesn't interrupt the flow |
| `done` | `{ usage?, messageKey? }` | Finished. A `messageKey` means it ended on a limit warning (e.g. step cap) |
| `error` | `{ messageKey, code?, params? }` | Failed and terminated |

### Endpoints that return SSE

| Endpoint | Purpose |
|---|---|
| `POST /sessions/{id}/chat` | Main chat (agent loop) |
| `POST /datasources/import` | Import a data file, with progress |
| `POST /datasources/sync` | Reconcile data sources, streaming diffs and results |
| `POST /db/sql-chat` | SQL assistant chat |
| `POST /reports/{id}/chat` | Report writing chat |
| `POST /evidence-forms/{id}/chat` | Evidence form writing chat |

Always consume these with `consumeSseGeneric` from `lib/api/sse.ts` — don't write a separate parser.

### Config entities (one pattern)

`models` / `rules` / `skills` / `kb/providers` / `mcp/servers` / `templates` all follow:

```
GET    /<res>            list (?scope=global|project)
POST   /<res>            create
PATCH  /<res>/{id}       update
DELETE /<res>/{id}       delete
POST   /<res>/{id}/test  connectivity test (models / kb / mcp only)
```

## Config scope

Almost every config entity carries a `scope`:

- `global` lives in `~/.fireeye/`, shared across all projects
- `project` lives in the current workspace's `.fireeye/config/`

Reads merge **global ⊕ project, with project overriding global**. List endpoints take `?scope=` to pick one layer.

## Adding an endpoint

1. Add `@router.get/post/...` to the matching module under `api/`
2. Raise `ApiError` on failure; don't build a `JSONResponse` yourself
3. Use SSE only when live feedback is needed; ordinary requests always return JSON
4. Define request/response types in `packages/shared/src/types.ts` (if the frontend needs them)
5. Add the frontend wrapper in `apps/renderer/src/lib/api/<domain>.ts`
