## 文档分工

这个仓库的文档分三类，别混着找：

- **`docs/dev/`**：当前实现的参考手册，分 [`zh/`](./) 与 [`en/`](../en/) 两个语种。描述的是**现在的代码**，代码变了就该跟着改。
- **`docs/plans/`**：按阶段 / 日期记的实施记录与设计方案。是**历史**——记录当时为什么这么做，不代表现在的实现。里面有已废弃的方案，不要照抄。
- **`docs/design/`**：UI 设计稿（`.pen` 源文件与预览图）和界面设计说明。

`docs/plans/fireeyeaud-design.md` 是早期的总体设计稿，产品定位、约束和部分数据格式约定仍然有效，但其中 Phase 1–7 的实施计划早已完成并超出，工具数量和目录结构都以代码为准。

## 改文档的规矩

- 本目录的文档写**事实**，不写“计划做”的东西。没实现的能力不要写进来。
- 涉及具体行为（端口、上限、错误码、文件名）时，写之前先回去看一眼代码——这些值会变。
- `docs/plans/` 保持原样，不要回头去改历史记录。要纠正事实，改本目录。
